# everytime-novel — 全流程网络小说写作系统

[English](README_EN.md) | 简体中文

> **让 AI 写长篇不崩的网文写作系统。** 写长篇最怕三件事：写到几十章人设崩了、前后剧情对不上、满屏 AI 味。
> 这套系统把写作拆成「先规划、后动笔」的两阶段流水线：
> 规划阶段生成全书细纲并稽核通过才准写正文，每批正文还要过 20 个维度的稽核。
> 去 AI 味既能写的时候顺手守住，也能事后单独跑一遍——它不绑定写作流程，随时可以脱开单用。

## 它替你盯住了什么

| 写长篇时你会遇到 | 这套系统的做法 |
|---|---|
| 伏笔埋了就忘，收不回来 | 细纲阶段就标注每条伏笔的埋设/回收时机，稽核逐条对照检查 |
| 角色名、技能名、金钱等级写着写着就漂 | 角色名以设定.md 为唯一真源，写手缺名即停、不许自己编名；货币链/物品链逐章对账 |
| 「仿佛」「骤然」「与此同时」满屏 AI 味 | 50+ 禁用词零容忍、7 类高频句式设上限，另有句式密度/模板段落指纹/注水章三项专项稽核 |
| 细纲只做到开头几十章，后面裸写崩盘 | 细纲完成度校验：细纲数量对不上规划章数，直接卡住不许开写 |
| 章与章之间衔接生硬 | 写手每章读完上一章全文和本章细纲再动笔，串行推进不断档 |
| 全文一股 AI 腔 | 去 AI 味可耦合也可独立：写的时候守住语言禁令，写完用脚本批量清符号、扫篇章；只改文风，不动情节和人物 |
| AI 味到底还有没有，凭感觉说 | 自带检测脚本，逐条给出规则编号和行号，不靠"读起来像不像" |

这套流程不是纸上设计：作者自己写的一本网文（《听说这棍能擀面？》，495 章）就是用它写完的，路上踩的坑沉淀成 52 条记录，随包分发（lessons.md）。

## 三十秒上手

```bash
skillhub install everytime-novel
```

（`skillhub` 是技能市场 CLI。已装过就不用再跑——直接对 AI 说下面那句话。）

装好后对 AI 说一句：

```
我要写一本都市小说
```

## 怎么确认装好了

AI 不会直接开写，而是先和你逐项确认设定——世界观、主角、金手指、规则，每确认一项就当场写进 `设定.md`。出现这个动作，就是装好了。

如果它不问设定直接开写，说明没装上：跑 `skillhub list` 看看 `everytime-novel` 在不在列表里。

## 四个入口，写到哪都能接上

| 你的状态 | 对 AI 说 | 它会做什么 |
|---|---|---|
| 只有一个想法 | 「我要写一本 XX 小说」 | 和你聊设定 → 大纲 → 卷纲 → 全部细纲 → 稽核通过、你点头后才开写 |
| 已经有细纲 | 「从 ch111 开始写」 | 按阶段批量写正文，每批写完自动稽核、修复后进下一批 |
| 有一摞草稿 | 「对 vol02 去 AI 味」 | 先跑检测脚本定位，全绿就一个字不改；有命中才逐处改，输出到 deaid/ 目录，情节人物不动 |
| 已经写成全书 | 「审查全书」 | 20 个维度逐卷审查，再做跨卷交叉对比（矛盾、伏笔、时间线） |
| 想让 AI 学你的手感 | 「定风格 DNA」 | 拿你 ≥20 章正文蒸馏出语言指纹，之后照你的句式节奏写（可选，不问就不做） |

## 核心机制：两阶段批量模式

```
规划阶段（全部完成才进入执行）：
  卷纲 → 细纲批次1 → 细纲批次2 → … → 全部细纲就绪 → 细纲稽核

执行阶段（按批次写正文）：
  正文批次1 → 稽核 → 修复 → 正文批次2 → 稽核 → …
```

一个阶段 = 卷纲里的一个故事段落，约 15–20 章。1M 上下文模型下一个阶段约 87,500 tokens，装得下。

### 写手每章读什么

| 读 | 用途 |
|---|---|
| 本章细纲（【本章状态】【本章事件】【伏笔】【禁止事项】块） | 剧情节拍、状态变化、伏笔动作的执行依据 |
| 上一章全文 | 衔接：位置、时间、情绪、持有物品都接得上 |
| 设定摘要（随写手指令下发） | 拿到真实角色名与关键设定 |

稽核再对照设定.md 原文（角色表、技能、规则、伏笔清单）和细纲，逐项检查正文。

### 两层稽核

| 层 | 时机 | 检查什么 |
|---|---|---|
| 细纲稽核 | 规划阶段 | 技能/角色是否在设定库、伏笔闭环、地点具体性、角色出场与伏笔回收时机 |
| 正文稽核 | 每批写完 | 20 个维度：货币链、物品链、场景衔接、代词、伏笔、句式密度、模板段落指纹、注水章、角色名三级一致、去 AI 味脚本扫描…… |

### 去 AI 味：可耦合，也可独立

它不是"最后必须跑一遍的收尾工序"，而是一个**能拆开用的能力**。两种用法都成立：

| 怎么用 | 你得到什么 |
|---|---|
| **耦合进写作** | 写手动笔时就守住语言禁令，从源头不产生 AI 味，省掉整轮返工 |
| **独立单跑** | 已经写完的稿子丢进来，只接收正文、只输出去 AI 味后的正文，情节人物一个字不动 |

耦合进写作时，按"改起来贵不贵"分层，不做无谓的重写：

| 层 | 什么时候做 | 做什么 |
|---|---|---|
| 语言层 | 写的时候 | 禁用词、句式上限、起手式、顿号、喻体……写手当场守住 |
| 符号层 | 写完之后 | 破折号、省略号格式、标点统一——脚本定位，逐处替换 |
| 篇章层 | 写完之后 | 相邻句同构、段首零回指——写时看不见，脚本统计 |
| 按需修补 | 只有上面报错才做 | 派子代理改，且只改命中处，未命中的逐字保留 |

**不写小说也能单用它。** `scripts/check_ai_tone.py` 是独立检测脚本，拿任何中文文本跑都行，输出规则编号 + 行号，只读不写、不改你的文件。全绿就什么都不用做——它把"要求"变成"事实"。

## 项目目录约定

```
项目根目录/
├── drafts/volXX/chXXX_draft.md     # 正文草稿
├── settings/
│   ├── 设定.md                     # 权威源：角色、技能、规则、伏笔清单
│   ├── 本书语言DNA.md              # 写法真相文件（可选，定过 DNA 才有）
│   ├── 大纲.md
│   └── 卷纲_volXX.md
├── dna-corpus/                     # 风格蒸馏语料（可选，≥20 章人写正文）
├── chapters/volXX/chXXX.md         # 细纲
├── deaid/volXX/                    # 去AI味产出
├── reports/                        # 稽核与跨卷报告
└── PROGRESS.md
```

## 它自带两个脚本

| 脚本 | 干什么 | 自检 |
|---|---|---|
| `scripts/check_ai_tone.py` | 扫 14 条 AI 味规则，输出规则编号 + 行号 + 片段 | `--test` 16/16 通过 |
| `scripts/distill_dna.py` | 统计语言指纹：对话占比、句长、段落节奏、标点、语气词、章首章尾类型 | `--test` 11/11 通过 |

两个都是纯本地脚本，只读不写、不联网，随时可以单独拿来跑。

## 什么时候用不上它

- **短篇 / 单章**：它的价值在几十章以上的长篇——细纲门禁和跨卷审查，章数太少体现不出来。
- **已经有满意成稿、只想改文风**：单跑去 AI 味就够了，不用走整条流水线。
- **想让它替你构思剧情**：它管的是"别写崩"，不是"想出好故事"。设定和大纲仍然要你来定。
