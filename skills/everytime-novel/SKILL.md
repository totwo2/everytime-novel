# everytime-novel — 全流程网络小说写作系统

> 从一个想法，到一本完整的小说。
> 模块化耦合：**四个入口，从哪个节点接手都行**——但走哪条路由下面的路由表说了算，不是"随便挑一步"。

---

## 用法（30 秒上手）

**装：**

```bash
skillhub install everytime-novel
```

**用——对 AI 说一句话就够：**

```
我要写一本都市小说
```

**装完确认——怎么验证它真的生效：** AI 不会直接开写，而是先跟你逐项确认设定（世界观、主角、金手指、规则），
每确认一项就当场写进**项目根目录下的** `settings/设定.md`。**出现这个动作 = 装好了。**
如果它不问设定直接开写，说明没装上——跑 `skillhub list` 看 `everytime-novel` 在不在列表里。

---

## 适用边界：什么时候用不上它

- **短篇 / 单章**：它的价值在几十章以上的长篇——细纲门禁和跨卷审查，章数太少体现不出来。
- **已经有满意成稿、只想改文风**：单跑去 AI 味就够了，不用走整条流水线。
- **想让它替你构思剧情**：它管的是"别写崩"，不是"想出好故事"。设定和大纲仍然要你来定。

## 启动路由（AI必须先判断）

收到用户消息后，按以下顺序判断从哪个节点启动：

### 第一步：精确匹配

| 用户说 | 路由到 |
|--------|--------|
| “写小说” / “新书” / “帮我写一本” | outline-rules.md（设定阶段） |
| “生成大纲” / “写大纲” | outline-rules.md（大纲阶段） |
| “生成卷纲” / “写卷纲” | outline-rules.md（卷纲阶段） |
| “生成细纲” / “写细纲” | outline-rules.md（细纲阶段） |
| “写第X章” / “从chX写” / “帮我续写” / “接着写” | pipeline.md（正文写作） |
| “去AI味” / “deai” / “改得人味点” | deai-rules.md |
| “定风格DNA” / “蒸风格” / “语言DNA” / “照着XX的味写” | dna-rules.md（可选流程） |
| “审查” / “稽核” / “检查下” / “有矛盾吗” | pipeline.md → 检查流程 |
| “交叉对比” / “跨卷检查” | cross-check.md |
| “格式检查” / “统一格式” | format-rules.md |

### 第二步：语义判断

如果精确匹配失败，按语义判断：

```
“这稿子太AI了” → 去AI味 → deai-rules.md
“后面怎么安排” → 查看进度 → 读卷纲/PROGRESS.md
“有矛盾吗” → 检查 → 检查流程
“第150章写好了” → 可能要检查或继续写 → 问用户
“新项目” → 设定阶段 → outline-rules.md
```

### 第三步：问用户

如果语义也无法判断，直接问用户，给具体选项：

```
“你是要：
A) 续写正文
B) 去AI味
C) 检查正文
D) 生成大纲/细纲
E) 其他”
```

**不要猜，不要假设，直接问。**

### 检查场景的路由

用户说“检查”时，必须先问一个问题：

```
“你有细纲吗？
A) 有 → 按细纲+正文检查（更严格）
B) 没有 → 按纯正文检查（交叉检查矛盾和冲突）”
```

**两种检查的区别：**

| 检查类型 | 参照物 | 检查内容 |
|----------|--------|----------|
| 纯正文检查 | 只看正文 | 交叉检查：前后矛盾、内容冲突、角色一致性、时间线、伏笔遗漏 |
| 细纲+正文检查 | 细纲+正文 | 写手有没有按细纲写、技能对不对、伏笔有没有种 + 纯正文检查的所有项 |

## 四大场景完整流程

### 场景1：新用户

```
用户：“我想写一本xxx小说”
  ↓
主代理判断类型（升级文/言情/悬疑/混合）
  ↓
主代理和用户聊设定（6项通用 + 类型追加）
  每确认一个 → 立刻写入设定.md
  ↓
用户确认设定.md ✅
  ↓
◇ 可选：语言 DNA
  项目里没有 → 问一次「要不要先定本书语言 DNA？」（默认跳过）
  项目里已有 → 做复用检查：同体裁直接用；跨大类必须问怎么用
  两条路都不阻塞大纲，详见 dna-rules.md
  ↓
主代理生成大纲.md
  ↓
主代理生成卷纲（含阶段划分）
  ↓
⛔ 规划阶段门禁
  主代理生成本卷全部细纲（十要素+状态信息）
  → 细纲稽核（地点具体性/角色出场时机/伏笔回收时机）
  → 稽核通过
  → 用户确认"可以写正文"
  ↓
主代理派写手子代理（按阶段，串行不并发）
  prompt = 上章末尾段 + 本章细纲路径 + 设定摘要 + 写作规则 + 字数下限
  ↓
写手返回正文 → 主代理派稽核子代理
  prompt = 正文 + 细纲
  ↓
稽核返回报告 → 有问题 → 主代理修复
  ↓
下一阶段 → 重复
```

### 场景2：续写

```
用户：“帮我续写第150章”
  ↓
主代理检查：有设定/大纲/细纲吗？
  ↓
没有 → 逐个补充：
  1. 设定.md：从正文提取 → 和用户聊清楚
  2. 大纲/卷纲：从设定+正文生成
  3. 已有章节细纲：从正文提取状态 → 套进格式（不改正文）
  ↓
全部就绪 → 主代理派写手子代理
  prompt = 上章末尾段 + 本章细纲路径 + 设定摘要 + 写作规则 + 字数下限
  ↓
写手返回正文 → 稽核 → 修复 → 下一阶段
```

### 场景3：检查

```
用户：“检查下”
  ↓
主代理问：“你有细纲吗？”
  ↓
有 → 细纲+正文检查（更严格）
没有 → 纯正文检查（交叉检查矛盾和冲突）
  ↓
主代理派检查子代理
  - 纯正文检查：交叉检查前后矛盾、角色一致性、时间线、伏笔遗漏
  - 细纲+正文检查：写手有没有按细纲写、技能对不对、伏笔有没有种 + 纯正文检查全部
  ↓
检查子代理返回报告
  ↓
用户确认 → 要修复吗？
  ↓
要 → 主代理修复 → 再检查
不要 → 结束
```

### 场景4：去AI味（写时已守，这里只做验收与按需修补）

> 写手按 writer-rules 的「去AI味前置禁令」写的话，这里大概率是**全绿空跑**。
> 不是白跑——它把"要求"变成"事实"。写手守了规则 ≠ 规则真的守住了。

```
用户：“帮我去AI味”
  ↓
主代理跑检测脚本（scripts/check_ai_tone.py）
  ↓
全绿（R1/R2=0，其余在阈值内）→ 直接结束：不派子代理，一个字不改
  ↓
有命中 → 派去AI味子代理
  prompt = 正文 + 去AI味规则 + 命中清单
  （项目里有 settings/本书语言DNA.md 则一并交给子代理）
  ↓
去AI味子代理只改命中处，未命中逐字保留
  ↓
重跑脚本验收（R1/R2 必须为 0）
  ↓
用户确认 → 不满意 → 再改
满意 → 结束
```

### 调度总结

```
场景1（新用户）：主代理全程主导 → 派写手 → 派稽核
场景2（续写）  ：主代理补齐缺失 → 派写手 → 派稽核
场景3（检查）  ：主代理判断类型 → 派检查子代理
场景4（去AI味）：主代理直接派去AI味子代理
```

## 核心架构：两阶段批量模式

```
规划阶段（全部完成才进入执行）：
  卷纲 → 细纲批次1 → 细纲批次2 → ... → 全部细纲就绪 → 稽核细纲

执行阶段（按批次写正文）：
  正文批次1 → 稽核 → 修复 → 正文批次2 → 稽核 → ...
  （每章写完提取全文，作为下章输入）
```

**一个阶段 = 卷纲里的一个故事段落（~15-20章）**

**为什么串行不并发：**
- 子代理上下文隔离，并发写必然衔接断裂
- 每章需要读完上章全文才能自然过渡，不是只看结尾几行
- 状态靠细纲传递，叙事衔接靠上章全文传递，缺一不可

## 快速开始

1. **新项目**：读 `outline-rules.md`，从设定开始
2. **已有细纲**：读 `pipeline.md`，进入阶段批量写作
3. **已有草稿**：读 `deai-rules.md`，去AI味（独立流程）
4. **已有成稿**：读 `audit-rules.md` + `cross-check.md`，质量审查
5. **想定风格（可选）**：读 `dna-rules.md`，蒸馏本书语言 DNA（有 ≥20 章语料才做，跳过不影响任何流程）
