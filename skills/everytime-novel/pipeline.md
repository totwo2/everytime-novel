# pipeline.md - 全流程编排(Main专用)

> Main读这个文件。子代理不读。

---

## 不完整项目处理(续写场景)

用户可能只给正文让续写,没有设定/大纲/卷纲/细纲。AI必须先检查,再决定怎么做。

### 检查清单

收到续写请求后,先检查项目目录:

```
✅ 设定.md - 有没有?
✅ 大纲.md - 有没有?
✅ 卷纲 - 有没有?
✅ 细纲 - 有没有?
✅ 上章结尾 - 用户给的正文里有没有?
```

### 处理流程

```
用户:"帮我续写第150章"
    ↓
检查:项目目录里有没有设定/大纲/细纲?
    ↓
有 → 直接进入写作流程
没有 → 逐个补充
```

### 逐个补充流程

#### 第一步:设定.md

从正文提取,和用户聊清楚:
```
提取:角色名、技能、世界观、规则
写入设定.md → 用户确认
```

#### 第二步:大纲/卷纲

从设定.md + 已有正文生成:
```
读设定.md + 已有章节
生成大纲.md → 用户确认
生成卷纲_volXX.md(含阶段划分)
```

#### 第三步:已有章节的细纲

**不是重新写,是从正文提取状态,套进细纲格式:**
```
对每个已有章节:
  读正文 → 提取:
    - 场景
    - 出场人物
    - 使用的技能
    - 货币/物品变化
    - 伏笔(埋设/回收)
    - 结束状态
  写入细纲格式(十要素+状态信息)
```

#### 第四步:续写

从已有章节的结束状态开始,生成后续细纲,写正文。

### 关键:已有章节不改

已有章节的正文不改,只是提取状态信息填进细纲格式。让后续章节能衔接上。

### 问用户补充(引导式)

不要问"你有什么设定",要问具体问题:

```
"我从正文里提取了以下信息:
- 主角:{设定.md里的主角名},{等级/命格}
- 女主:{设定.md里的女主名},{等级/命格}
- 当前位置:{地点}

还有几个问题需要确认:
1. {主角名}的X3技能是什么?(我看正文里提到了'{技能名}')
2. 当前货币是多少?
3. 有什么伏笔需要继续推进?
4. 你希望续写的剧情往哪个方向走?"
```

> 上面是**格式示例**：角色名、等级、技能一律从本书 `settings/设定.md` 和正文提取，禁止照抄示例名。

**关键:**
- 先展示AI已经提取的内容,让用户确认
- 再问缺失的部分,给具体问题
- 不要让用户从零开始讲
- 如果用户也说不清楚,就按正文推断,写入设定.md让用户确认

## 两阶段架构

```
规划阶段(全部完成才进入执行):
  卷纲 → 细纲批次1 → 细纲批次2 → ... → 全部细纲就绪

执行阶段(按批次写正文):
  正文批次1 → 稽核 → 正文批次2 → 稽核 → ...
```

---

## 阶段划分

一个阶段 = 卷纲里的一个故事段落,约15-20章。

**标准(1M上下文模型):**
- 理想:15-20章
- 上限:30章
- 不足15章也可以(按故事段落来,不硬凑)

---

## 规划阶段流程

### 1. 生成卷纲
```
读设定.md → 生成卷纲(含阶段划分)
输出:settings/卷纲_volXX.md
```

### 2. 按批次生成细纲
```
对每个阶段:
  读设定.md + 卷纲 + 上批次细纲
  → 生成本阶段细纲(~15章)
  → 输出:chapters/volXX/chXXX.md ~ chYYY.md
```

### 3. 稽核全部细纲
```
读设定.md + 全卷细纲
→ 检查:技能是否在设定库、角色是否在角色表、伏笔是否一致
→ 输出:reports/review_outline_volXX.md
```

**规划阶段全部完成 → 进入执行阶段**

### ⛔ 规划阶段门禁(铁律)

**以下条件全部满足才能进入执行阶段,缺一不可:**
1. 卷纲已生成且用户确认
2. 本卷所有阶段的细纲全部生成(不能只写第一阶段就开正文)
3. 全部细纲通过稽核(review_outline_volXX.md 存在且无P0问题)
4. **细纲完成度校验通过**:扫描 `chapters/volXX/` 细纲文件数 == 卷纲规划章数(如 vol01规划75章→必须有75个细纲文件),缺则阻塞,禁止"只做75章就停"(实战《七零》细纲只做到ch075,后145章无细纲直接写导致质量失控)
5. 用户明确说"开始写正文"或"可以写了"

**违反记录:**
- 测试中AI在只完成第一卷卷纲稽核后就问要不要写正文,用户拒绝
- 实战《七零》细纲只做到ch075,后145章无细纲直接写,质量失控
- 原因:约束写在流程描述里但没有门禁检查点
- 修复:增加以上硬性门禁(含第4条完成度校验),AI每步都要确认

## 执行阶段流程

### 1. 写手写正文(串行)
```
每章独立派出 writer 子代理:
├── prompt 内容: 上章末尾段 + 本章细纲文件路径(含章节号) + 设定摘要 + 写作规则 + 字数下限
├── 写中只需: 读上章全文 + 读本章细纲 → spawn writer
├── writer 子代理自己: 用 read 工具读上章全文 + 细纲【本章状态】【本章事件】块
├── 写手写完一章 → 写中提取全文 → 作为下章输入
├── 写手自己做格式检查(禁用词/破折号/字数/代词)
└── 阅后即焚
```

**为什么串行不并发:**
- 子代理上下文隔离,并发写必然衔接断裂
- 每章需要读完上章全文才能自然过渡(不是只看末100字——大模型上下文够)
- 测试中改成并发后,子代理各写各的,对不上

**写中每章的工具调用要控制在3次以内:**
1. 读上章全文(用于判断衔接)
2. spawn writer 子代理
3. 检查输出(字数+禁用词+破折号)

⚠️ 写中不需要代读上章全文、不需要提取状态块/事件块——这些由 writer 子代理自己用 read 工具读

**writer 子代理的强制读步骤(写在prompt里,writer自己执行):**
1. 用 read 工具读【上章全文】 → 完整理解位置/时间/女主心理/持有物品/现金/上章情绪
2. 用 read 工具读【本章细纲文件】 → 找到「本章状态」「场景设计」「事件」「伏笔」「禁止事项」块，完全遵守
3. 对比上章末状态和本章开始状态 → 确保衔接
4. 正文的场景、位置、人物出场必须和细纲一致，不能自己编

### 2. 稽核正文(按批次)
```
派出 audit 子代理
├── prompt = 本阶段正文 + 细纲 + 设定.md
├── 检查:是否符合细纲、角色行为、技能使用、伏笔、代词
├── 输出稽核报告
└── 阅后即焚
```

### 3. 修复
```
Main 读稽核报告
├── P0 → 必须修复
├── P1 → 建议修复
└── P2 → 可接受
```

### 4. 进入下一阶段

## Writer 子代理 Prompt 模板

```
你是专业网络小说写手。你的唯一任务是按细纲写正文。

## 强制读步骤（开始写前必做，缺一即失败）
1. 用 read 工具读【上章全文】（路径见下方），完整理解位置/时间/女主心理/持有物品/现金/上章情绪基调
2. 用 read 工具读【本章细纲文件】（路径见下方），找到本章的「本章状态」块和「场景设计」块，确保你的正文完全遵守细纲的场景、位置、人物、冲突设计
3. 从细纲文件里找到「本章事件」块和「伏笔」块，确保正文推进细纲要求的事件和伏笔
4. 对比上章末状态和本章开始状态：本章开始状态必须=上章末状态。如果对不上，停下来检查，不要瞎写。

## 铁律（违反任何一条即失败）
1. 严格按细纲写，不能自己加戏、加角色、加情节
2. 技能名必须和细纲一字不差，不能简写、改名、自创
3. 状态（阶位、货币、物品、位置）必须和细纲一致
4. 每章最少{字数下限}中文字，最多不超过最少字数的150%
5. 禁用词完整列表（以下任何一个都不能出现）：
   与此同时/从而/于是/因此/值得注意的是/综上所述/不言而喻/毋庸置疑/赋能/闭环/重塑/未来可期/意义重大/深刻剖析/系统性/应运而生/众所周知/发人深省/总而言之/璀璨/瑰丽/绚烂/心潮澎湃/热血沸腾/令人不安/令人窒息/非常震惊/令人震惊/令人惊叹/难以置信/顺滑/丝滑/首先/其次/值得一提的是/然后/最后/再次/而且/并且/因而/此外/不可或缺/由此可见/打造/引人注目/一气呵成/仿佛/宛如/骤然/缓缓/淡淡/如同/瞬间
   注意：以上词无一例外，没有“特殊情况下可以用”的说法
6. 破折号"——"完全禁止，无例外。对话中断用省略号"……"替代
7. 正文用"他"指男主，用"她"指女主，不能搞混
8. 开头第一句必须是人物的具体动作或对话，禁止以下任何开头方式：
   - 氛围描写（"舱内很安静""引擎低鸣""星光闪烁"）
   - 情绪独白（"他不知道这意味着什么""有些话不需要说出来"）
   - 悬念钩子（"暗红色的光""声音突然消失了"）
   - 时间流逝（"时间过了很久""不知过了多久"）
   - 静止状态（"他站在那里""他闭上眼睛"）
9. 结尾最后一段必须包含人物的具体动作（走路/说话/拿东西/转头/按下按钮等），禁止以下任何结尾方式：
   - 静止状态（"他闭上了眼睛""两人对视""他没有说话"）
   - 氛围收尾（"舱内很安静""引擎低鸣""星光洒进来"）
   - 情绪留白（"有些话不需要说出来""她没有问他想说什么"）
   - 未规划的悬念钩子（"暗红色的光""声音突然消失了"）

## 上章全文文件路径
{上一章正文文件绝对路径，如 /path/to/ch085_draft.md}

## 本章细纲文件路径
{本章细纲文件绝对路径，如 /path/to/chapters/vol02/ch076-090.md，内含本章的【本章状态】块和【本章事件】块}

## 本章章节号
ch086

## 输出
写到 {项目路径}/drafts/volXX/chXXX_draft.md
标题格式:# 第XXX章:标题
写完报告字数。

## 不能做
- 不能写"本章完"
- 不能写作者按
- 不能偏离细纲
- 不能自己编技能名
- 不能改变状态(除非细纲里写了变化)
- 不能用破折号"--",对话中断用省略号"......"
- 不能用以上禁用词表中的任何一个词
- 开头第一句不能是氛围/情绪/悬念/时间流逝/静止状态,必须是人物动作或对话
- 结尾最后一段不能是静止状态/氛围收尾/情绪留白/未规划悬念,必须是人物具体动作
- 字数不能超过最少字数的150%
```
