# audit-rules.md — 内容审计规则

> 审计子代理读这个文件。从内容层面检查质量。
> 每个维度必须逐章检查，不能跳过。

---

## 审计维度

### 1. 货币链（逐章必查）
- 每章开头现金 = 上章末现金（不能多也不能少）
- 花钱/赚钱必须有具体数字和计算过程
- 计算不能出错（起始 - 花费 + 收入 = 结束）
- 现金数字必须在正文中显式出现
- 输出：每章现金起始→变动→结束 的完整对照表

### 2. 物品链（逐章必查）
- 细纲【本章状态】栏里列出的物品必须在正文中体现
- 有前后作用的物品才追踪（在哪里用、数量变化）
- 一次性物品（肥皂、红糖等）不追踪，不写到状态栏
- 交易消耗的物品必须从清单中移除
- 新增物品必须有获得过程
- 输出：每章物品清单对照表（细纲【本章状态】栏 vs 正文）

**追踪类**（逐章比对，来源+本章用途+去留必须可追溯）
- 格式：`物品名（来源→本章用途）`，用途空洞 = P1
- 票证：布票、肉票、粮票等
- 信物：信件、礼物（对剧情有推进作用的）
- 证据：账本、票据、文件等
- 关键道具：金手指相关物品
- 追踪类凭空消失/出现 = P0

**记录类**（首次出现注来源，不强制追踪去留）
- 家长里短的小礼物/一次性消耗品
- 无剧情功能的装饰物品

### 3. 场景衔接（逐章必查）
- 每章开头场景/位置必须和细纲一致
- 章末→章初必须有过渡段（起床→出门→路上→到达），不能硬切
- 禁止：章末在A地，章初直接在B地开始动作
- 检查方式：对比上章末段和本章首段的场景/位置

### 4. 章首格式（逐章必查）
- 开头第一句必须是人物的具体动作或对话
- 禁止以下开头方式：
  - 时间开头（"天亮了""清晨""零点"）
  - 氛围描写（"舱内很安静""引擎低鸣"）
  - 情绪独白（"他不知道这意味着什么"）
  - 悬念钩子（"暗红色的光""声音突然消失了"）
  - 静止状态（"他站在那里""他闭上眼睛"）

### 5. 章尾格式（逐章必查）
- 结尾最后一段必须包含人物的具体动作
- 禁止以下结尾方式：
  - 静止状态（"他闭上了眼睛""两人对视"）
  - 氛围收尾（"舱内很安静""引擎低鸣"）
  - 情绪留白（"有些话不需要说出来"）
  - 未规划的悬念钩子（"暗红色的光""声音突然消失了"）
- 禁止套路化：不能每章用同一个结尾模式

### 6. 禁止事项执行（逐章必查）
- 细纲里写了"不能写XX"的，正文有没有写
- 检查方式：读细纲的"禁止事项"块，逐条对比正文

### 7. 角色一致性
- 名字是否前后一致
- 性别代词是否正确（女主=她，男主=他；具体角色名以设定.md为准，禁止预填占位名）
- 能力/命格是否前后一致
- 称呼关系是否一致
- 性格是否前后连贯

### 8. 情节连贯性
- 时间线是否合理（日夜交替、季节变化）
- 因果关系是否成立
- 是否有重复场景/重复对话/重复段落
- 章节衔接是否自然
- 角色心理转变是否有触发事件

### 9. 写作质量
- 禁用词残留（逐词检查）
- 破折号"——"残留（正文中零容忍）
- 第三人称叙述中出现"我"
- 重复句式/重复段落
- 过度使用特定句式

### 10. 伏笔追踪
- 已埋设的伏笔是否被回收
- 是否有悬而未决的线索
- 钩子植入是否自然
- 关键伏笔线是否持续被提及（不能连续5章以上不提）

### 11. 字数统计
- 每章字数是否达标（从设定.md读取下限）
- 字数不足 → P1
- 字数超过上限150% → 检查是否有注水

### 12. 对话质量
- 对话是否自然（不AI味）
- 语气词使用是否合理
- 角色说话风格是否区分

### 13. 世界观一致性
- 设定是否前后矛盾
- 术语使用是否统一
- 技能/等级体系是否一致
- 时代背景是否准确（物价、货币、票证等）

### 14. 关键情节点具体性（铁律）
- 关键情节点必须包含具体要素：谁、什么、哪里、多少
- 禁止模糊描述："某地"、"一些事"、"做了一件事"、"某种原因"
- 新闻类情节点必须包含：具体地点、具体事件、具体数据
- 违反 = P0，必须修复

### 15. 票证使用合理性（年代文专用）
**适用**：1970年代等票证时代背景

**检查项**：
- [ ] 票证数量是否合理（1尺布=33厘米，不够做衣服；2两肉只够一人份）
- [ ] 票证是否有使用场景（不能无限积累不用）
- [ ] 使用场景是否有情节功能（推动人际关系/剧情）
- [ ] 是否票证+钱同时使用（1970年代买东西必须两者兼备）
- [ ] 票证增减是否逐章衔接（上章结束=下章开始）

**问题分级**：
- 数量不合理（如1尺布做衣服）= P1
- 票证凭空消失/出现且无说明 = P0
- 有票证但从不使用（不符合时代背景）= P1
- 只用钱不用票证或只用票证不用钱 = P1

---

### 16. 句式重复密度（铁律）
**适用**：全书（尤其悬疑/日常章）
- 统计全书的“睁眼/闭眼/睁开眼睛/闭上眼睛/深吸一口气”等AI惯用句式
- 单章 ≤ 2次，全书累计 ≤ 50次（超出即P1，批量替换）
- 连续3章用同一句式收尾/开头 = P1
- 输出：句式频次表（句式/出现章数/总次数）

### 17. 模板段落指纹（铁律）
**适用**：场景重复型段落（财务室/烧火/月报/修炼/吃饭等）
- 相同 >40字 的段落出现 ≥ 3次 = P0（说明写手复制粘贴没改）
- 同一场景的固定描写（如“推门进去，灶台上的水正冒着热气”）跨章重复 ≥ 3次 = P1
- 输出：重复段落清单（原文/章号/次数）

### 18. 注水章密度（铁律）
**适用**：连续多章情节推进极慢
- 连续 N章（N≥3）情节密度 < 细纲预期的 50% = P0（如“五连章注水”：5章≈1.5章内容）
- 判定依据：细纲要求3个事件，正文只写1个且无有效过渡 = 注水
- 处理方式：触发重写，不跳过（实战 ch136-140 跳过导致终稿留坑）
- 输出：注水章清单（章号/细纲预期事件数/正文实际事件数）

### 19. 角色名一致性（三级：设定/细纲/正文）
**适用**：全书（最易打架的维度，P0级）
- 设定.md 的角色正式名 = 唯一真源（SSOT）
- 细纲里的角色名必须 = 设定.md 里的正式名（不一致 = P0）
- 正文里的角色名必须 = 设定.md 里的正式名（不一致 = P0）
- 禁止 skill 模板预填占位名（如“勋空”），实战曾因预填导致三层打架（设定“待命名”/模板“勋空”/正文“陈卫国”）
- 输出：角色名对照表（设定名/细纲名/正文名/是否一致）

---

### 20. 去AI味脚本扫描（铁律）
**适用**：每批正文（稽核阶段，与维度 9「写作质量」互补）

维度 9 靠人（子代理）扫禁用词和破折号；本维度靠脚本扫**需要统计与上下文判断**的项，两者不重叠。

**做法**：对本批每章跑一次
```
python3 scripts/check_ai_tone.py {草稿路径}
```

**判定**：
| 脚本输出 | 级别 |
|---|---|
| R1 禁用词 或 R2 破折号 非零 | **P0**，必须修复 |
| R3/R4/R8/R9/R11/R13/R14 超阈值 | **P1** |
| R5/R6/R7/R12 超阈值 | **P1**，但需人工确认（这几项有上下文豁免，见 deai-rules 第四节） |

**稽核子代理不要自己凭语感判断 R5（顿号过密）、R6（相邻句同构）、R7（段首零回指）**——交给脚本算，稽核只吃脚本结论。这三项在对话、列表、系统面板内有豁免，人眼扫必错。

- 输出：各章命中清单（规则编号/行号/片段），附脚本原始输出

## 问题优先级

| 级别 | 定义 | 处理 |
|------|------|------|
| P0 | 影响阅读/逻辑矛盾/角色混乱 | 必须修复 |

## 全量稽核流程（全书细纲完成后）

### 执行规范
1. **分批执行**：每批不超过30章，超过则拆分
2. **逐章检查15+5项**：货币链、物品链、场景衔接、章首格式、章尾格式、禁止事项、角色一致性、情节连贯性、写作质量、伏笔追踪、字数、对话质量、世界观 + 关键情节点具体性 + 票证使用合理性 + 句式重复密度 + 模板段落指纹 + 注水章密度 + 角色名一致性（三级）+ 去AI味脚本扫描
3. **独立出报告**：每批独立报告，最后合并
4. **稽核与修复分离**：稽核子代理只出报告不修复，修复子代理只修复不稽核
5. **修复后验证**：修复完成后必须重新验证链路

### 货币链验证脚本
```python
import re
with open("文件路径", "r") as f:
    content = f.read()
chapters = re.split(r'## 第(\d+)章', content)
results = []
for i in range(1, len(chapters), 2):
    ch_num = int(chapters[i])
    ch_body = chapters[i+1] if i+1 < len(chapters) else ""
    # 定位"本章状态"段落取第一个货币匹配
    start_sec = re.search(r'### 本章状态(.*?)(?=###|\Z)', ch_body, re.DOTALL)
    end_sec = re.search(r'### 本章结束状态(.*?)(===|\Z)', ch_body, re.DOTALL)
    if start_sec and end_sec:
        sm = re.search(r'货币[：:]\s*(\d+)元(\d+)角', start_sec.group(1))
        em = re.search(r'货币[：:]\s*(\d+)元(\d+)角', end_sec.group(1))
        if sm and em:
            results.append((ch_num, f"{sm.group(1)}元{sm.group(2)}角", f"{em.group(1)}元{em.group(2)}角"))
prev = None
for ch, s, e in results:
    if prev and s != prev:
        print(f"❌ ch{ch}: 期望{prev}，实际{s}")
    prev = e
```

### 修复任务拆分原则
- 每个修复任务只处理1-2个问题
- 场景/情绪修复、价格修复、物品修复分开执行
- 价格修改必须连锁更新所有相关章节的货币值
- 修复后用脚本验证链路不断
