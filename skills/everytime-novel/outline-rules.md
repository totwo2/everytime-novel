# outline-rules.md — 大纲生成规则

> Main读这个文件。从想法到细纲的全流程。

---

## 四层架构

```
设定（一次性）→ 大纲（一次性）→ 卷纲（每卷）→ 细纲（每章）
   地基层            基因层           规划层          执行层
```

---

## 第一层：设定（地基层）

输入：用户的原始想法（一句话/一段话/一个概念）

输出：
- `settings/设定.md` — 世界观、人物、规则、技能库
- `settings/角色表.md` — 主要角色清单

### 铁律：讨论完立刻写文件

**AI说“记住了”不算，写进设定.md才算。**

每讨论完一个点，立刻写进设定.md：
```
讨论：主角性格是冷静型 → 立刻写进设定.md
讨论：这个技能有代价 → 立刻写进设定.md
讨论：结局是开放式 → 立刻写进设定.md
```

**不要等全部讨论完再写。** 上下文会丢失，AI会遗忘，AI会篡改你要的东西。
设定.md是你的“外部记忆”——AI上下文丢了没关系，文件还在。

### 设定阶段交互流程

```
1. 用户给初始想法（一句话/一段话）
2. AI提问：逐个确认核心要素
3. 每确认一个 → 立刻写入设定.md
4. 用户确认设定.md ✅（唯一的确认点）
5. 允许小细节留白（路人的技能、支线细节，后面补）
```

### 设定讨论流程

```
1. 用户给初始想法（一句话/一段话）
2. AI判断小说类型（单一类型 or 混合类型）
3. 根据类型确定讨论要素清单
4. 逐个讨论，每确认一个立刻写入设定.md
5. 用户确认设定.md ✅（唯一的确认点）
6. 允许小细节留白（路人的技能、支线细节，后面补）
```

### 通用设定项（所有类型必须问）

除了类型相关的要素，所有类型都必须问：

- **每章最少字数** — 用户要求的下限（如2400/3000/4000），写入设定.md，派写手时带上

### 可选设定项：本书语言 DNA（问一次，默认跳过）

**定位：可选项，不是必做流程。** 跳过不影响开写，不影响大纲、卷纲、细纲任何环节。

**只在三个条件同时满足时问一次**：
1. 项目里还没有 `settings/本书语言DNA.md`
2. 用户没说过"直接开写""别问那么多"
3. 存在可用语料（用户提到有对标作品，或本项目已有 ≥20 章人写正文）

**问法**（问一次，给三个选项，说明默认值）：

```
开写前要不要先定这本书的语言 DNA（写法指纹）？

A) 有对标作品 → 给我 ≥20 章免费章，我蒸一份
B) 你自己写过 ≥20 章 → 蒸你自己的稿子
C) 跳过（默认）→ 写到 20 章再补，不影响现在开写
```

**规则**：
- 用户选 C、答"不用"、或没正面回应 → **直接进大纲，不再追问**
- 用户选 A/B → 走 `dna-rules.md`，蒸完再进大纲（DNA 只管写法，不影响大纲内容，也可以与大纲并行）
- **只问一次**。不要在卷纲、细纲、正文阶段重复问；用户中途主动说"蒸个风格"时再走 `dna-rules.md`
- 语料不够 20 章 → 如实说明，建议先写、攒够再蒸，不要硬蒸

**为什么是可选项**：没有语料时硬蒸出来的 DNA 是幻觉，比没有更糟（详见 `dna-rules.md` 第九节）。

### 已有 DNA 时：复用检查（不是问"要不要蒸"，是问"怎么用"）

若项目里**已经有** `settings/本书语言DNA.md`（续写第二本、换卷后体裁变了、或沿用旧项目的 DNA），**不要再问"要不要蒸"**，改做一次复用检查：

1. 读 DNA 头部的**体裁标签**
2. 与本次要写的体裁比对：

| 比对 | 动作 |
|---|---|
| 同体裁 | 直接用，**不打扰用户** |
| 同大类不同小类 | 提一句"已有 X 体裁的 DNA"，**默认沿用 L1+L2**，L3 仅供参考 |
| **跨大类**（玄幻 / 近代 / 科幻 之间） | **必须问用户**，不许默默沿用 |

跨大类的问法：

```
检测到已有《{旧书名}》的语言 DNA（体裁：{旧体裁}），本次这本是{新体裁}。要怎么用？

A) 只沿用 L1+L2（推荐）→ 保住你的手感（句长/对话密度/标点习惯），放掉类型相关的叙事习惯
B) 整体沿用 → 手感+套路都带过来，接受类型特征错配
C) 重新蒸馏 → 有新语料时选这个
```

**核心区分**：L1 表层语言（句长、对话占比、标点、语气词）是**作者手感，跨类型稳定**；L3 叙事习惯（主角行为逻辑、金手指节奏）**强绑定类型**，跨大类必须重蒸。手感能带走，套路带不走。详见 `dna-rules.md` 第二节。

### ⚠️ 角色名单一真源（SSOT）铁律（v1.3.5 新增）

**实战教训：**《七零年代苟道日常》设定.md写男主"待命名"、skill模板预填"勋空"、正文用"陈卫国"，三层打架→50+处混用P0，7/2才统一。根因是设定阶段没把名字定死就往下走。

**铁律（设定阶段必须执行）：**
1. **主角姓名在设定阶段必须定死**，写入设定.md，禁止"待命名""TBD""XX"等占位逃逸
2. 设定.md的角色正式名 = 全书唯一真源（SSOT）
3. generate细纲/正文时，角色名从设定.md注入，不依赖skill模板预填
4. writer-rules.md / pipeline.md 模板里的角色名示例一律视为"示例"，新书须替换为本书真实名
5. 设定确认点（用户确认设定.md✅）前，若角色名仍空缺，**阻塞后续所有流程**

### 类型判断

AI根据用户初始想法，判断小说属于哪种类型（可混合）：

| 类型 | 特征关键词 | 示例 |
|------|-----------|------|
| 升级文/修仙文 | 等级、技能、修炼、升级、战力、突破 | 定海号、凡人修仙传 |
| 言情文 | 爱情、情感、CP、甜宠、虐恋 | 都市言情、古言 |
| 悬疑文 | 案件、推理、线索、诡计、真相 | 推理小说、悬疑剧 |
| 科幻文 | 科技、星际、文明、AI、未来 | 硬科幻、太空歌剧 |
| 历史文 | 朝代、权谋、宫斗、架空历史 | 宫斗文、权谋文 |
| 都市文 | 现代、职场、商战、都市 | 都市爽文、职场文 |
| 奇幻文 | 魔法、异世界、种族、神祇 | 西幻、日式奇幻 |

**混合类型判断：** 如果用户想法同时涉及多个类型（如"星际+神话+升级"），AI应识别出所有相关类型，并合并讨论要素。

### 各类型必讨论要素

#### 所有类型通用（6项必填）

1. **核心卖点** — 一句话说清楚这本书讲什么
2. **主角完整人设** — 性格+说话方式+行为底线+成长弧线
3. **核心人物关系图** — 谁和谁什么关系
4. **世界观硬规则** — 不可违反的设定
5. **大结局** — 故事怎么收
6. **绝对禁忌** — 不能写什么

#### 升级文/修仙文（追加6项）

7. **力量体系** — 等级划分+技能定义+升级路径
8. **技能组合规则** — 技能能否组合、组合限制
9. **反噬/代价体系** — 使用能力的代价和恢复方式
10. **反派体系** — 反派派系/组织/差异化
11. **升级节点** — 哪些章节/事件触发升级
12. **战力闭环规则** — 如何防止战力崩坏

#### 言情文（追加3项）

7. **情感线节拍** — 相遇→暧昧→确认→危机→HE 的节奏
8. **社会关系网** — 家庭、职场、社交圈
9. **核心矛盾** — 阻碍两人在一起的根本原因

#### 悬疑文（追加3项）

7. **案件结构** — 案件数量+类型+复杂度
8. **线索体系** — 线索如何埋设和回收
9. **诡计设计** — 核心诡计/反转

#### 科幻文（追加3项）

7. **科技体系** — 核心科技设定+限制
8. **文明架构** — 社会结构+阵营
9. **探索节奏** — 发现真相的节奏

#### 历史文（追加3项）

7. **历史框架** — 真实历史 or 架空
8. **权力体系** — 官职、势力、派系
9. **核心冲突** — 权谋/宫斗/战争

#### 都市文（追加3项）

7. **社会背景** — 行业、阶层、时代
8. **核心冲突** — 职场/商战/家庭
9. **成长路径** — 主角如何逆袭

#### 奇幻文（追加3项）

7. **魔法/能力体系** — 能力来源+限制+等级
8. **种族/阵营** — 各种族/阵营的设定
9. **世界架构** — 大陆/位面/神界

### 混合类型处理

当小说是混合类型时，AI应合并所有相关类型的讨论要素：

```
例：定海号 = 科幻 + 升级文 + 言情
讨论要素 = 通用6项 + 科幻3项 + 升级6项 + 言情3项 = 18项
（去重后约12-15项）
```

**去重规则：** 如果多个类型有相似要素（如"世界观硬规则"和"文明架构"），合并为一个讨论项，但内容要覆盖所有相关类型的需求。

## 第二层：大纲（基因层）

输入：设定

输出：
- `settings/大纲.md` — 全书故事线

### 大纲结构

```
# 全书大纲

## 核心冲突
一句话概括全书矛盾

## 三幕结构
第一幕（vol01-vol02）：建立世界观，主角出场，核心冲突确立
第二幕（vol03-vol04）：冲突升级，主角成长，真相逐步揭露
第三幕（vol05-vol06）：最终决战，冲突解决，收束

## 关键转折点
列出3-5个改变故事走向的节点

## 伏笔清单
列出全书需要埋设和回收的主要伏笔

> ⚠️ **伏笔单一真源（SSOT）铁律（v1.3.5 清理后）**
> 伏笔的唯一权威载体是：**设定.md 的伏笔清单 + 卷纲伏笔目标 + 细纲伏笔块**。
> **不另设 `hooks_tracking.yaml` 或任何独立追踪文件**——该文件曾是 v1.0 目录树里的幻影引用（只声明不生成、无消费方），已删除。
> 审计阶段的“伏笔追踪”维度靠逐章读正文推断，不依赖任何 yaml。

## 第三层：卷纲（规划层）

每卷（20-30章）开始前生成。

输入：大纲 + 上卷状态

输出：`settings/卷纲_volXX.md`

### 卷纲内容

每章3-5个节拍 + 禁止事项 + 伏笔目标

```markdown
# VolXX 卷纲

## 本卷主线
一句话概括

## 章节规划
| 章节 | 标题 | 核心事件 | 伏笔 |
|------|------|----------|------|
| chXXX | 标题 | 事件1/事件2/事件3 | 埋设:XX / 回收:XX |

## 禁止事项
本卷不能发生什么

## 伏笔目标
本卷需要埋设/回收的伏笔
```

## 第四层：细纲（执行层）

每卷写作前按批次生成。**全部细纲生成完才开始写正文。**

输入：卷纲 + 设定.md + 上批次细纲

输出：`chapters/volXX/chXXX.md`

### 生成节奏

```
规划阶段（全部完成才进入执行）：
  卷纲 → 细纲批次1 → 细纲批次2 → ... → 全部细纲就绪
  稽核细纲

执行阶段（按批次写正文）：
  正文批次1 → 稽核 → 正文批次2 → 稽核 → ...
```

**关键约束：规划阶段全部完成才开始执行。**

### 细纲格式

```markdown
# 第XXX章：标题

## 一、场景设计
**主场景**：{具体地点，必须精确到可画面化，如"浮舟遗迹中层·第三试炼室"、"北辰学院·训练场B区"，不能写"XX公司"、"某个地方"这种模糊表述}
- 时间：{白天/夜晚/具体时刻}
- 环境：{天气、光线、温度、周围有什么}
- 氛围：{紧张/压抑/轻松/诡异等}

## 二、人物出场
| 人物 | 命格/等级 | 出场方式 | 本场作用 |

## 三、核心冲突
本章的核心矛盾是什么

## 四、转折设计
1. 起始状态
2. 触发事件
3. 转折点
4. 新状态

## 五、伏笔
本章需要埋设/回收的伏笔

## 六、禁止事项
本章不能写什么
```

## 细纲时机校验（伏笔和角色出场）

细纲生成时必须对照卷纲的章节规划，校验以下时机：

### 角色出场时机
- 角色首次出场必须在卷纲规划的章节范围内
- 提前出场超过10章 → 算异常，需要用户确认
- 提前出场超过30章 → 算P0，必须修正

### 伏笔回收时机
- 伏笔回收必须在卷纲规划的章节范围内
- 提前回收超过30章 → 算异常，需要用户确认
- 提前回收超过50章 → 算P0，必须修正
- 延迟回收（超过规划章节）→ 可以，但要在细纲里标注原因

### 校验方法
```
生成细纲批次N时：
  读卷纲 → 找到本批次章节对应的伏笔目标
  检查：
    - 本批次是否有不该出场的角色？
    - 本批次是否有不该回收的伏笔？
    - 本批次是否有遗漏的伏笔埋设？
  发现异常 → 报告用户，等确认后再继续
```

## 信息传递原则

**核心：写手只读两样东西，设定文件是gate的检查标准。**

### 写手读什么

| 文件 | 内容 | 来源 |
|------|------|------|
| 细纲 | 剧情节拍 + 当前状态 + 本章参考信息 | 用户确认 |
| 上章结尾 | 最后20行，衔接用 | 上章正文 |

**写手不读设定文件。** 设定文件的内容（角色技能、规则、伏笔清单）通过细纲传递给写手。

### Gate读什么

| 文件 | 用途 |
|------|------|
| 设定.md | 角色表、技能、规则、伏笔清单（权威源） |
| 细纲 | 本章要求（交叉校验） |

Gate对照设定文件检查正文：技能对不对、角色名对不对、伏笔有没有遗漏。

### 为什么这样设计

踩坑经验：写手读多了不看，读少了自己发挥。
- 写手只读细纲+上章结尾 = 最小负担，不会“没看到”
- 设定文件给gate做校验 = 机器兜底，不依赖写手自觉

## 三层锚点机制

### 锚点规则

| 层级 | 锚定方式 | 说明 |
|------|----------|------|
| **大纲** | 无锚点 | 直接根据设定生成 |
| **卷纲** | +大纲锚点 | 卷纲开头附大纲摘要 |
| **细纲** | +大纲锚点 + 卷纲锚点 + 前5章摘要 | 双锚点+防写偏保险 |

### 前5章摘要机制

细纲按卷纲阶段分批生成，每批读取前一批最后5章摘要作为锚定：

```
第1批（ch01-ch10）：不读前序
第2批（ch11-ch30）：读ch06-ch10摘要
第3批（ch31-ch60）：读ch26-ch30摘要
以此类推...
```

**前5章摘要的本质**：细纲本身就充当摘要（含十要素），可直接用于承接，防矛盾保一致。

### 十要素（每章细纲必须包含）

1. **场景** — 本章发生在哪里（必须精确到可画面化，如"浮舟遗迹中层·第三试炼室"，禁止"XX公司"、"某个地方"）
2. **人物** — 本章出场角色
3. **目标** — 本章要推进什么
4. **冲突** — 本章的核心矛盾
5. **转折** — 意外事件（可无）
6. **情感** — 本章的情绪基调
7. **技能** — 本章使用的技能（必须标注阶位+效果）
8. **经济** — 本章的货币/物品变化
9. **伏笔** — 本章种下或回收的伏笔（必须注明：埋设/回收/推进）
10. **禁止** — 本章不能写什么

### 细纲必须包含的状态信息

每章细纲开头必须写明：

```markdown
## 本章状态
- 位置：{具体地点，必须精确到可画面化}
- {角色A}：{阶位}，可用技能 = {技能名}({简要效果})、{技能名}({简要效果})
- {角色B}：{等级}，可用技能 = {技能名}、{技能名}
- 货币：{金额}
- 物品：{清单}
```

每章细纲结尾必须写明：

```markdown
## 本章结束状态
- 位置：{具体地点，如果和本章状态不同则写明}
- {角色A}：{阶位}，精神力{百分比}（战斗消耗{百分比}）
- 货币：{金额}
- 新增物品：{物品名}
```

> 上面两个块是**格式示例**：角色名、阶位、技能名一律从本书 `settings/设定.md` 提取，禁止照抄示例名（实战曾因模板预填名导致设定/细纲/正文三层打架 P0）。

**关键规则：**
- 技能必须标注阶位（X1/X2/X3）和简要效果
- 结束状态必须和下一章的开始状态一致
- 写手不能自己编技能名，只能用细纲里列出的
- 状态变化必须有理由（战斗消耗、修复恢复、物资获取等）
- **地点必须精确到可画面化**（如"浮舟遗迹中层·第三试炼室"，不能写"XX公司"）

### Brief必填7项

1. 核心卖点一句话
2. 主角完整人设（性格+说话方式+行为底线+成长弧线）
3. 核心人物关系图
4. 世界观硬规则
5. 金手指/核心能力（上限+代价+成长路径）
6. 大结局
7. 绝对禁忌

## 物品追踪规则
- **只有有前后作用的物品才写入状态栏**：在哪里用、数量变化
- **一次性物品不写入状态栏**：肥皂、红糖等没有后续作用的物品
- **状态栏是写手的唯一物品参考**：写手只管状态栏里的东西
