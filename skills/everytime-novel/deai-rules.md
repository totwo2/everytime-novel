# deai-rules.md — 去AI味规则（编辑视角）· 融合版 v1.0

> DeAI子代理读这个文件。目标：把AI味重的稿子改成人味。
> 与writer-rules共享规则库，但视角不同——编辑改稿，不是作者写稿。
>
> v1.0 融合：495 章实战清单（禁用词/破折号/句式上限/章首章尾）+ lieflat-less-ai-tone 的算子化框架
> （白名单 / 信息守恒 / 最小改动 / 逐项验收）与篇章层特征（段首零回指 / 相邻句同构）。
> **语域声明**：lieflat 的原始语料是非虚构论述文，其倍率数字在网文叙事语域没有直接效力。
> 本文件只采用它的算子思想与触发标记，不引用其倍率作为依据。

配套脚本：`scripts/check_ai_tone.py`（先跑脚本拿命中清单，再按编号逐条改，改完重跑验收）。

## 定位：写时约束 + 写后验收（不是事后返工）

去AI味不是一个"完稿后洗一遍"的工序。它是**拆成三段**的：

```
① 写时管（语言层，成本高）→ 写手在 writer-rules 里守住：禁用词/句式上限/起手式/顿号/名词化/喻体/序数词/空转句/翻译腔/章首章尾
② 事后清（符号层，成本极低）→ 脚本定位 + 逐处按语境替换：破折号/省略号格式/标点统一
③ 事后扫（篇章层，写时看不见）→ 脚本统计：相邻句同构 R6 / 段首零回指 R7 / 跨章类
④ 按需修补 → 只有 ②③ 报错时才派 deai 子代理，只改命中处
```

**① 做对了，后面就是空跑。** 这才是"写的时候就按去AI味写"的正确形态——不是取消验收，是让验收无事可做。

### 分层判据：看「事后修它要花多少成本」

| 层 | 规则 | 谁管 | 为什么 |
|---|---|---|---|
| **语言层**（要重写句子） | R1 禁用词、R3 句式上限、R4 起手式、R5 顿号、R8 名词化、R9 喻体、R10 序数词、R11 空转句、R12 翻译腔、R13 章首章尾 | **写时管** | 事后改要重组句子，贵。写手的注意力只花在这里 |
| **符号层**（可批量替换） | **R2 破折号、R14 省略号与标点** | **事后清** | 脚本一把定位，成本极低。**写时不用管**——每写一句去数破折号只会打断思路 |
| **篇章层**（要统计视角） | **R6 相邻句同构、R7 段首零回指** | **事后扫** | 写手在上下文里有连贯感，天然感知不到"这一段三句同骨架""这句评论缺回指" |
| **跨章类**（稽核 16/17/18） | 句式密度、模板段落指纹、注水章 | 事后扫 | 需要跨章统计或对照细纲 |

**符号类叫"批量清"不等于"一把梭替换"**：破折号在不同语境要换成不同标点（解释型→逗号、延续型→句号、语气型→删除），**脚本只负责定位，替换逐处看语境**。

**为什么脚本那一次不能省**：它是"事实核验"，不是"返工"。写手守了规则 ≠ 规则真的守住了——和"AI 说记住了不算，写进设定.md 才算"是同一个道理。守规则是**要求**，跑脚本是**事实**。

- 去AI味只接收正文，只输出去AI味后的正文
- 什么时候用、用不用，用户决定；**② 验收建议每章都跑**（几秒钟，写对了不改一个字）
- 不读设定.md——只改文风，不改内容（角色名/代词校验见 R14，需对照设定.md）

## 核心区别

| | writer-rules（作者） | deai-rules（编辑） |
|--|---------------------|-------------------|
| 视角 | 从无到有写 | 从有到优改 |
| 任务 | 创作正文 | 识别+替换AI味 |
| 去AI味 | 附带约束 | 核心任务 |
| 改动范围 | 全文 | 只改有问题的地方 |

## 一、硬性边界（最高优先级，凌驾于所有改写冲动）

### 1. 白名单式改写
只处理本文件列出的 R1–R14。**没有命中任何规则的句子必须逐字保留。** 一句话即使命中，也只能改动解决该问题所必需的部分——不得顺便润色，不得替换没问题的词，不得调整语气、详略或信息密度。对某处是否命中没把握时，保持原文。

### 2. 信息守恒：不许新增，不许删减
以下内容**绝不能**凭改写添加，哪怕只是为了让句子"更像人写的"：
姓名、机构名、地名、职务；数字、比例、金额、时长、次数；日期、时间、先后顺序；引语、对话、别人的说法；因果、动机、心理活动；任何原文没写的细节、场景或案例。

反方向同样禁止：不能删掉原文的观点、结论、限定词和让步（「可能」「通常」「据说」「有些」）。把"可能"改成"一定"是篡改判断强度，不是去 AI 味。

**验收办法**：改写后的每个实词，都要能在原文指出出处。指不出来就是新增，撤销。

### 3. 不动结构
标题层级、章节顺序、段落数量与顺序、列表、引用、代码块的位置必须原样保留。不概括、不扩写、不删减观点、不重组叙事顺序。

### 4. 网文专属裁决（与 lieflat 原规则不同，以本条为准）

| 争议项 | lieflat（论述文） | 本文件（网文） | 裁决理由 |
|---|---|---|---|
| 情感标签 → 身体外化 | 禁止（违反信息守恒） | **允许** | 网文必须 show don't tell。**边界**：外化内容只能是原文已给情绪的可信外化，不得新增情节、回忆、人物、数字 |
| 比喻 | 比喻不是 AI 味 | 不删比喻本身，只禁「理想化职业人格喻体」；普通比喻按次数上限 | 网文比喻会泛滥，但全面禁比喻会伤文采 |
| 句长/段长参差 | 明确不改 | 保留"打破节奏"，但**只在连续 3 段以上同构时才动**，禁止机械的"长短交替" | 段落节奏是商业需要，机械切句会写崩 |
| 破折号 | 改逗号/句号 | **全禁，零容忍** | everytime 已验证更严标准更适合网文 |
| 首先/其次/最后 | 正文里与人类无差别，不必改 | **禁用词全禁** | 叙事语域里这些连接词出戏 |
| 设问/问句 | 不改 | 不改 | 一致 |

### 5. 冲突时以本书语言DNA为准——但要防"AI 味被固化成风格"
若项目存在风格蒸馏产物（本项目产物：`settings/本书语言DNA.md`；兼容外部产物：`语言DNA.md` / `Writing-DNA.md`），先读它。**DNA 与本文规则冲突时，以 DNA 为准**（那是目标作者的真实写法）。

⚠️ **前提例外**：蒸馏产物本身要过一遍 `check_ai_tone.py`。若 DNA 里记录的高频模式命中了 R1–R14（说明语料本身是 AI 生成的，蒸馏把 AI 味固化成了"风格"），该条目标记为**待人工确认**，不作为豁免依据。

## 二、不作为改写理由（硬约束，不是参考）

以下看着像 AI 味，实测站不住或语域不适用，**不得据此改文字**：

| 特征 | 为什么不改 |
|---|---|
| 句长、段长不够参差 | 论述文实测与人类写作无差别。不要为了制造节奏机械切句 |
| 单字虚词偏少（就/很/了） | 方向是补不是删，补虚词无法验收，会把正式文改成口语 |
| 被动句、名词化长句本身 | 现代汉语书面语正常写法 |
| 正文设问、反问、问句小标题 | 人类用得比 AI 多，删掉更不像人写 |
| 比喻本身、比喻独立成段 | 人类用得比 AI 多。只处理 R9 那一类喻体 |
| 句内同构排比（"提升效率，降低成本"） | 人类用得不比 AI 少。只处理**句间**同构（R6） |
| 对话口语化、语气词 | 网文需要，不是 AI 痕迹 |
| 修仙/系统流术语、面板、状态栏 | 体裁设定，不是 AI 痕迹 |

## 三、改写规则（编号与脚本一致）

### R1 禁用词（零容忍）
```
与此同时 从而 于是 因此 值得注意的是 综上所述 不言而喻 毋庸置疑 赋能 闭环
重塑 未来可期 意义重大 深刻剖析 系统性 应运而生 众所周知 发人深省 总而言之
璀璨 瑰丽 绚烂 心潮澎湃 热血沸腾 令人不安 令人窒息 非常震惊 令人震惊 令人惊叹
难以置信 顺滑 丝滑 首先 其次 值得一提的是 然后 最后 再次 而且 并且 因而 此外
不可或缺 由此可见 打造 引人注目 一气呵成 仿佛 宛如 骤然 缓缓 淡淡 如同 瞬间
```
替换策略：「最后」→「末尾/收尾/删除」；「然后」→「接着/逗号连接/删除」；「而且」→「删除，用逗号连接」；「仿佛/宛如/如同」→「像/好像/具体描写」。

### R2 破折号（零容忍）
绝对禁止 `——`，无例外。对话中断用 `……` 替代。解释型→逗号；延续型→句号/逗号；语气型→删除。

> **符号层**：写手不必逐句自查，本环节批量定位、逐处按语境替换。

### R3 句式次数上限（每章）

| 句式 | 上限/章 |
|---|---|
| 「不是A，是B」类翻案腔 | ≤ 3 次 |
| 「像是」 | ≤ 3 次 |
| 「微微」 | ≤ 2 次 |
| 「XX没有立刻回答」 | ≤ 2 次 |
| 「沉默了几秒」 | ≤ 2 次 |
| 「点了点头」 | ≤ 3 次 |
| 睁眼/闭眼/睁开眼睛/闭上眼睛/深吸一口气（合计） | ≤ 2 次 |

翻案腔改法：从正面下判断，先给判断再给依据。
> ❌ 真正的壁垒不是技术，而是认知。 → ✅ 真正的壁垒是认知。

### R4 起手式（禁用）
「说白了」「说穿了」「先说结论」「众所周知」「值得注意的是」「不难看出」「总而言之」→ 删掉后直接给判断。

### R5 顿号罗列过密
**触发**：一个分句内 3 个以上顿号、连起 4 项以上并列成分。
**改法**：能概括就别逐项列举；必须保留时改变其中一项的句法。
**不改**：物品/菜名/清单的列举语境；Markdown 列表内部；必须完整列出的场合。

### R6 相邻句结构同构（句间，非句内）
**触发**：同一段内相邻三句，逗号数量相同、成分顺序相同、长度接近（典型是"主语＋动词＋宾语，＋补充说明"连续复现）。
**改法**：打散其中一句的句法——合并、拆分、换语序、改短句。只改句子内部，不动段落顺序，不删信息。
> ❌ 这个功能上线后用户反馈很好。团队的开发效率提升明显。下一步的优化方向已经确定。
> ✅ 这个功能上线后用户反馈很好，团队开发效率也提升了。下一步优化什么，已经定了。

一段里并排 3 个以上平级案例时，合并同类项或把次要的压成半句。**不改**：叙事推进（先发生什么→怎么做→结果）；对话和引语；文学体裁的有意排比。

### R7 段首零回指评论
**触发**：非首段以「听起来/看起来/说到底/值得注意/更重要的是/关键在于/问题在于/意味着/不难看出/有意思的是」开头，且整句没有「这/那/其/此/上面/它/他/她」等回指上文的成分。
**改法**：补一个回指词或点明评论对象，多数情况加一个「这」字就够。
> ❌ 听起来像一条功能描述，其实底下换掉了更根本的东西。
> ✅ 这听起来像一条功能描述，其实底下换掉了更根本的东西。

**不改**：首段；原文已有回指成分；对话和引语内部。

### R8 名词化结构
**触发**：「完成了对……的……」「实现了……的提升」「进行了……的优化」「作出了……的调整」。
**改法**：恢复动词。
> ❌ 团队完成了对流程的优化。 → ✅ 团队把流程改顺了。

### R9 拟人化喻体（理想化职业人格）
**触发**：「像/相当于 + 一个/一位 + 职业角色（导师/秘书/助手/顾问/审查员/实习生）」+ 褒义修饰（智慧的/永不疲倦的/全能的），或后接「不仅……更……」。
**改法**：换成它实际做了什么，或改用具体的人当喻体。
> ❌ 这相当于为团队配备了一个永不疲倦、秒级响应的初级审查员。
> ✅ 它不会疲倦，响应在秒级，能承担初级审查的活。

**不改**：具体的人当喻体（「像一个老师傅」）；修仙/系统流里属于设定的拟人（器灵、系统精灵）。

### R10 序数词当小标题（低优先级）
**触发**：小标题以「一、二、三」或「第一、第二」编号，且连续 3 个以上。
**改法**：删编号，保留小标题原文。**不改**：正文里的「首先……其次」；编号承担指代功能时；Markdown 有序列表。

### R11 空转句引出列表
**触发**：正文一行以冒号收尾，紧接着列表项或编号，且这句话去掉后信息不减。
**改法**：写成有内容的判断，或直接删掉让列表接上上文。不能删列表项。
> ❌ 我见过的几种典型场景： → ✅ 这几种场景我都见过。

**不改**：引出人物原话的冒号；对话行内的冒号；列表项内部的冒号。

### R12 翻译腔（只处理三种）
1. **过长前置定语**：中心名词前修饰成分超过 15 字，或「的」连续两个以上。→ 段内拆成两个分句。
   > ❌ 这是一个能够让团队在不增加人力的情况下显著提升审核速度的工具。
   > ✅ 这个工具能显著提升审核速度，不需要增加人力。
2. **「当……时」前置时间从句** → 删「当」「时」，让从句直接作前一分句。**不改**：删掉后时间关系变模糊时。
3. **前置话题壳**：句首「对于……来说/对……而言/就……而言/关于……/在……方面」，而后面句子本来就以该对象为主语或宾语。→ 把对象放到主语位，删掉壳子。

**不处理**：被动句、名词化长句本身、专业术语、修仙术语、公文固定表达。

### R13 章首与章尾格式
- **章首第一句**必须是人物的具体动作或对话。禁止：时间开头、氛围描写、情绪独白、悬念钩子、静止状态。
- **章尾最后一段**必须包含人物的具体动作。禁止：静止状态、氛围收尾、情绪留白、未规划的悬念钩子；禁止每章同一个结尾模式。

### R14 标点、格式与角色名
> **符号层**：省略号与标点部分写手不必自查，本环节批量清；人称与角色名部分属语言层，写时就要守。

- 省略号统一 `……`。禁止 `......`、`...`、`······`。
- 第三人称叙述禁止「我」（对话中可保留）。
- 角色名与代词以 `设定.md` 为唯一真源（SSOT），禁止混用、禁止预填占位名。

## 四、对话与体裁豁免

R3/R5/R6/R7/R11/R12 在以下位置**一律不生效**：
1. 中文引号内的对话内容 2. 以引号开头的整行对话 3. 列表项、引用块、代码块内部
4. 系统面板、状态栏、修仙/系统流格式化文本 5. 引用他人原文

**R1（禁用词）与 R2（破折号）无豁免**——对话里同样零容忍。

## 五、保持不变的（十要素）

1. 情节走向 2. 人物行为 3. 对话内容 4. 场景设定 5. 人物关系
6. 情感基调 7. 叙事节奏 8. 悬念张力 9. 细节 10. 主题寓意

可以改的：句式结构、修饰词、过渡句、比喻方式、段落节奏（仅在连续 3 段以上同构时）。

## 前置

   python3 scripts/check_ai_tone.py {草稿路径}

## 改写规则
{deai-rules.md 的 R1-R14 与豁免条款}

## 原文
{草稿内容}
